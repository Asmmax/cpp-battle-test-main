# **Известные недостатки и сомнения по решению**
1. Singleton системы используются только в действиях (Action) и командах (Command). 
Возможно лучше будет пробрасывать им контекст систем. Иначе сейчас потенциально одна система может завязаться на другую.
2. Возможно стоит завести прототипы в виде data asset-ов, регистрировать их по id, и спаунить Unit-ов из них.
Сейчас спаун с команды выглядит громоздко, но в целом с этим ничего не сделать, разве что вынести общие функции.
3. Возможно стоит завести теги/трейты для Unit-ов, и проверять их в action-фильтрах, тогда можно избавиться от хранения данных о unit-ах в системах.
